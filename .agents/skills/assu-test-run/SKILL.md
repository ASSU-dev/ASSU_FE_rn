# ASSU 테스트 실행

승인된 범위의 테스트 파일을 실행하고, 실패 원인을 분류해 자동 수정 또는 개발자 확인으로 분기한다. 목표는 테스트 통과가 아니라, 승인된 사용자 규칙이 실제로 보호되는지를 검증하는 것이다.

## 수행 절차

1. `docs/testing-strategy.md`의 실행 기준과 개발자가 승인한 제품 규칙·기대 결과·테스트 범위를 읽는다. 승인 내용이 불분명하면 실행 전에 확인한다.
2. 새로 작성하거나 수정한 테스트 파일만 실행한다. `yarn test <keyword>`는 regex 매칭이라 의도치 않은 파일까지 포함되므로 사용하지 않고, `yarn test -- --testPathPattern='^<정확한 상대 경로>$'` 형식으로 승인된 파일만 지정한다. 전체 테스트, coverage, watch는 별도 요청이나 승인 없이 실행하지 않는다.

   **jest-expo 멀티 프로젝트 주의**: 저장소가 `jest-expo` preset을 사용하면 기본 설정에 따라 ios·android 프로젝트가 각자 러너로 돌아 테스트 하나가 2회 이상 실행될 수 있다. 실행 수가 "3회 한도"에 영향을 주면 `--selectProjects ios`처럼 단일 프로젝트만 지정하거나, Jest 설정의 `projects`를 확인해 중복 실행을 제거한 뒤 재실행한다.
3. 실패 원인을 다음 네 가지로 구분해 처리한다.
   - **테스트 코드·mock·fixture·실행 환경 문제**: 승인된 기대 동작은 유지한 채 테스트 측 파일만 수정해 재실행한다. 공용 Jest 설정·전역 setup·의존성 파일 변경은 개발자 승인 없이 하지 않는다.
   - **기존 구현과 테스트 기댓값 불일치**: 어떤 정책을 기준으로 판단해야 하는지 개발자에게 확인하고, 승인된 정책 기준으로만 테스트를 수정한다.
   - **제품 코드 변경 필요**: 원인·영향 범위·수정안·대상 파일을 개발자에게 제시하고 대기한다. 승인된 범위만 수정한 뒤 Jest를 재실행한다.
   - **반복 실행해도 불안정 (flaky 의심)**: 재시도로 덮지 않고 재현 조건과 flaky 가능성을 기록해 보고한다.
4. 한 작업의 대상 테스트는 최초 실행을 포함해 최대 3회 실행한다. 한도 안에서 통과하지 못하면 중단하고 시도 내역과 미해결 원인을 보고한다.
5. 성공한 경우에만 `docs/ai-qa/test-run-log.md`에 실행 명령, 시도 내역, 최종 결과, 변경 내역을 기록한다. 실패하거나 중단한 실행은 누적 기록에 남기지 않는다. 원본 로그 전체는 기록하지 않는다.
6. 테스트별로 어떤 정책을 검증했는지, 무엇을 수정했는지, 실행 결과가 무엇인지 함께 요약해 개발자가 테스트의 적합성을 최종 검토할 수 있게 보고한다.

## 제한 사항

- 테스트 통과만을 목표로 기댓값을 희석하거나 skip 처리하지 않는다.
- 공용 Jest 설정·전역 setup·의존성 파일은 개발자 승인 없이 수정하지 않는다.
- 제품 코드는 개발자가 구체적인 수정 범위를 승인한 뒤에만 변경한다.
- 승인된 범위를 넘는 테스트 추가·수정은 하지 않는다.
- 전체 테스트, coverage, watch는 별도 요청이나 승인 없이 실행하지 않는다.
- typecheck와 lint는 자동 실행하지 않는다.
